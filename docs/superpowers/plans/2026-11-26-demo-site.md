# Public demo site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public, login-free demo of the lights app at `demoxmas.weiss-audio.com` (Control and Create only), with extra demo-only strings, where visitors can play and edit live but never save, and nothing can reach the real lights.

**Architecture:** The web app is built a second time in Vite mode `demo` (`packages/web/dist-demo`). In that build `call()` in `api.ts` hands every request to an in-browser stand-in that holds the tab's own show, started from `/demo/show.json`. A tiny read-only Fastify server (`packages/server/src/demo.ts`, its own container on `127.0.0.1:8091`) serves the built files, the snapshot (built from the real `/data/show.json` with an allow-list plus `config/demo-extras.json`) and the house model.

**Tech Stack:** TypeScript, React 19, Vite 8 (rolldown), Fastify 5, vitest, Docker compose, Cloudflare tunnel.

**Spec:** `docs/superpowers/specs/2026-11-26-demo-site-design.md`

## Global Constraints

- Node lives in `~/.local/node/bin` (prefix `PATH=~/.local/node/bin:$PATH` on every npm/npx/node command).
- Commit as `git -c user.name=sweiss105 -c user.email=sweiss105@proton.me commit …`, message ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work only in the worktree `/home/weissaudio/wt-demo` (branch `demo-site`); never touch the main checkout or the live container until the PR is merged.
- The real bundle (`packages/web/dist`) must contain no demo code: the demo switch is `import.meta.env.MODE === 'demo'` so Vite folds it away.
- The demo server answers only GET and HEAD; it has no token, sets no cookies, opens no sockets other than its listener, and writes nothing.
- The snapshot is an allow-list: `layout`, `scenes`, `playlists`, `presets`, `palettes`, `activeScene`, `stage`, `output` (`brightness`, `gamma`, `transition` only), `house` (without part `file`). Never `schedule`, coordinates, `playing`, `lastScene`, `scheduleInWindow`, controller hosts (all become `demo.invalid`).
- Refusal message (stand-in, every storing call): `This is a demo: saving is turned off.` (HTTP-like status 403).
- Ribbon text: `Demo: nothing here is connected to real lights, and saving is off.`
- Disabled-button tooltip: `Saving is turned off in the demo`.
- No Setup page in the demo: Control and Create only; `#/setup…`, `#map`, `#map-demo` open Control. No Schedule tab in the demo.
- Demo port 8091 on `127.0.0.1`; container on Docker's bridge network, `./data:/data:ro`, read-only root, `cap_drop: [ALL]`, `no-new-privileges`.

## Review Focus

1. A visitor's old bookmark or shared link to `#/setup/house` or `#map` → opens Control, never a blank page or a Setup panel (Task 5 test).
2. A stored scene that doesn't validate against the merged demo layout (or a playlist entry naming a deleted scene) → Go shows the error message and the stage stays as it was; a playlist skips the missing scene (Task 4 tests).
3. The real `show.json` is replaced while a snapshot is being built, or is briefly unreadable → the demo keeps serving the last good snapshot (Task 3 test).
4. Keyboard paths around disabled buttons (the Save shortcut in Create, Enter in a name dialog) → the refusal message, never a silent "saved" state (Task 6 test on `sceneFlow`; the stand-in refusal covers the rest).
5. Two tabs open on the demo → each has its own stage; `status.rev` never changes, so neither tab reloads the other (Task 4 test).

Rules for `buildDemoSnapshot`:
- Controllers: copies with `host: 'demo.invalid'`, plus `{ id: 'demo', name: 'Demo strings (not real)', host: 'demo.invalid', pixelCount: <sum of extra counts> }`. Extra runs get `controller: 'demo'` and consecutive `start`s from 0; `dome` runs become `positions: domePositions(...)` with `dome` removed.
- Groups: real groups; `porch-real` = the real `porch` group as it was; `porch` = real porch runs + every extra run id; plus the extras file's groups.
- `stage`: `show.stage` only when `show.activeScene` names a stored scene, else `null`.
- `domePositions`: deterministic (no randomness): rings of a half-ellipsoid whose centre is the box's centre at floor height `min[1]`, radii half the box's x/z extents and its full height; points on the upper 80 % of the dome, pushed 0.03 m outward, ordered ring by ring with alternate rings reversed (zig-zag), exactly `count` points.
